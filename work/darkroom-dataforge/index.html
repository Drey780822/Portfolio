Darkroom DataForge

Structured data extraction, cross-page table reconstruction, and dataset generation engineered around the foundational principle: "Every extracted record should be traceable to its source."

Role

Software Systems Developer

Focus

Parsing Pipelines & Provenance Modeling

Core Pipeline

8-Stage Auditable Ingestion Workflow

Architecture

React, FastAPI, SQLAlchemy, PostgreSQL

1. The Problem Context

In academic research, public policy, and institutional analytics, critical statistical records are frequently locked inside complex unstructured documents: scanned government reports, multi-column survey evaluations, and technical manuals.

Standard Optical Character Recognition (OCR) tools fail catastrophically on these formats: tables spanning across page boundaries lose header coherence, numeric figures in adjacent columns merge together, and footnotes corrupt row records. Worse, once a table is extracted to a spreadsheet, there is rarely any machine-readable audit trail linking a specific cell back to its original page coordinates in the source PDF.

2. The Guiding Architectural Principle

Foundational Rule: "Every extracted record should be traceable to its source."

Rather than assuming an extraction algorithm will achieve 100% autonomous accuracy, DataForge treats data extraction as an evidence-gathering discipline. Every cell, row, and table entity maintains a foreign key pointer to its source document ID, page index, and bounding-box coordinates ([x0, y0, x1, y1]). This allows researchers to immediately inspect the source document directly beside the extracted record.

4. Technical Decisions & System Architecture

Component Technology Technical Rationale
User Interface React + TypeScript + Vite Fast client rendering and responsive canvas overlays for rendering interactive bounding-box highlights over PDF document viewports.
Backend Engine FastAPI (Python 3.11) Asynchronous endpoints capable of streaming document ingestion and processing tabular extraction algorithms efficiently.
Database Layer SQLAlchemy with Dual Engine Standardized on PostgreSQL for containerized team deployments and SQLite for isolated local developer testing without setup overhead.
Export Engine Pandas & OpenPyXL Provides type-safe dataset generation with metadata sheets containing provenance hashes.

5. My Role & Engineering Contribution

As a Systems Developer on this initiative:

  • Cross-Page Heuristics: Designed table stitching algorithms that detect continuation headers, repeated column patterns, and page-split table boundaries.
  • Provenance Modeling: Engineered the SQLAlchemy relational schema linking DocumentPage, TableEntity, RowRecord, and ProvenanceCoordinate.
  • Audit Trail System: Implemented a review log that records every human editor correction, timestamps edits, and tracks changes before final dataset commitment.
  • Export Pipeline: Built the multi-format export module allowing researchers to export verified data into clean CSV, JSON, or Excel files.

6. Limitations & Human-in-the-Loop Reality

We explicitly treat human review as an essential architectural component, not a temporary fallback:

  • Automated parsers can misinterpret complex multi-tier headers or skewed scans.
  • By providing researchers with an interactive review screen showing the source document side-by-side with extracted cells, anomalies are caught in seconds rather than contaminating published research datasets.
