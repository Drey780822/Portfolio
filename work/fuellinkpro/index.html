FuelLinkPro: On-Demand Fuel Delivery Platform

A distributed, three-sided marketplace connecting stranded motorists and commercial fleet managers with certified mobile fuel delivery drivers. Architected from requirements to production deployment.

Role

Co-Founder & Software Engineer

Period

November 2025 – Present

Domain

Geospatial Logistics & Payments

Live Website

fuellinkpro.com ↗

1. Project Overview & Problem Context

In South Africa, motorists traveling through rural routes, long-distance freight drivers, and construction plant operators frequently experience fuel depletion far from commercial filling stations. Traditional roadside assistance requires membership subscriptions, lacks real-time GPS visibility, and often takes hours to arrive.

FuelLinkPro was conceived to solve this critical logistical friction by providing an on-demand, mobile-first fuel dispatch network. The platform connects consumers with licensed mobile fuel carriers, allowing users to request petrol or diesel delivered directly to their pinned vehicle location.

2. Intended Users & Core Workflows

The platform coordinates three distinct user personas across synchronized state workflows:

  • Consumers / Fleet Operators: Pin vehicle geolocation via Google Maps, specify fuel type (Diesel 50ppm, Unleaded 95) and volume, preview pricing inclusive of delivery surcharges, authorize payments via PayFast, and monitor driver approach in real-time.
  • Certified Delivery Drivers: Receive broadcast dispatch alerts matching their operating radius, accept orders, follow turn-by-turn routing, verify customer identity at the destination, dispense fuel, and confirm delivery completion.
  • Platform Administrators: Monitor active orders, review driver safety certifications, audit PayFast merchant settlements, adjust regional pricing indices, and manage platform commission distributions.

3. My Role & Engineering Scope

As Co-Founder and Software Engineer, I took full individual ownership of the system's technical foundation:

  • Relational Architecture: Designed the complete PostgreSQL database schema with SQLAlchemy ORM, enforcing strict foreign key constraints, table normalization, and state machine enums for order lifecycles.
  • API Services: Implemented RESTful endpoints in Python using Flask, with token-based JSON Web Token (JWT) authentication and role-based permissions.
  • Payment Gateway Integration: Engineered the PayFast merchant integration with cryptographic signature validation (MD5/SHA-256 HMAC) and Instant Payment Notification (IPN) webhook handlers.
  • Real-Time Dispatch: Configured Flask-SocketIO with Redis message broker to broadcast bidirectional location coordinates and order state transitions.
  • Background Workers: Configured Celery asynchronous workers backed by Redis to manage automated timeout cancellations for unclaimed dispatches, generate digital receipts, and trigger Twilio SMS / SendGrid email updates.
  • Cloud Infrastructure: Containerized microservices using Docker and orchestrated an Nginx reverse proxy with SSL termination and Gunicorn WSGI process management.

5. Key Technical Decisions & Trade-Offs

Decision Choice Made Rationale & Engineering Trade-Off
Database Engine PostgreSQL + SQLAlchemy Transactional consistency (ACID) is non-negotiable for payment and inventory states. Trade-off: Schema changes require disciplined migration scripts via Flask-Migrate / Alembic.
Asynchronous Queue Celery + Redis Decouples long-running email/SMS notifications and order expiration timers from the synchronous HTTP request-response cycle.
Real-Time Tracking Flask-SocketIO + Redis Pub/Sub Enables persistent bi-directional communication for live driver coordinate streaming without excessive HTTP polling overhead.
Commission Model 70% Driver / 30% Platform Earlier proposals evaluated an 80/20 split; business evaluation shifted toward a 70/30 baseline to balance platform insurance and operational infrastructure costs.

6. Security, Reliability & Data Considerations

Operating a commercial financial transaction platform required defensive security measures:

  • Idempotent Payment Reconciliation: PayFast IPN webhooks are validated using source IP checks, cryptographic signature matching, and database-level unique transaction constraints to prevent duplicate fulfillment or double-charging.
  • Authentication & Secret Isolation: Passwords are hashed using bcrypt with salt rounds; JWT tokens enforce short lifespans with secure HTTP-only cookie storage; credentials and merchant passphrases are strictly isolated in server-side environment variables.
  • Order State Machine: Order transitions follow strict deterministic states (PENDING_PAYMENT → PAID → DISPATCHING → ACCEPTED → IN_TRANSIT → COMPLETED), preventing race conditions where multiple drivers could accept the same order.

7. Results & Verified Traction

The platform is live and in active deployment testing:

  • Client Rollout: Over 10 registered customers and over 15 vetted delivery drivers onboarded during initial route validations in the Johannesburg region.
  • Verified Capabilities: End-to-end payment capture through PayFast sandbox and production rails, real-time driver coordinate broadcasts, and automated SMS dispatch confirmations.
  • Metric Disclosure: These supplied figures reflect early rollout onboarding, not audited daily active volume or annualized commercial revenue.

8. Lessons Learned

Building FuelLinkPro from scratch provided invaluable engineering lessons:

  • Network Fault Tolerance: Mobile driver devices often experience intermittent cell tower handover. Building reconnection resilience and local coordinate batching in the driver client proved essential.
  • Defensive Webhooks: External payment gateways will retry failed webhook deliveries. Building strictly idempotent database handlers was vital to preventing corrupted state transitions.
