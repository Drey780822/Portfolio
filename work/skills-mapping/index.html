Wits Skills Mapping Platform

An AI-enabled occupational discovery and competency analysis platform. Bridges vocational research taxonomies with candidate CV data through telemetry collection and structured relational modeling.

1. Project Overview & Institutional Context

Under the Future of Learning stream at Wits Enterprise (in collaboration with the merSETA Darkroom Project), researchers and software engineers investigate how emerging technologies can address South Africa's critical skills gap.

Traditional career guidance models rely on rigid occupational classifications that fail to reflect fast-changing technological competencies. The Skills Mapping Platform is designed to bridge this divide by parsing unstructured candidate curriculum vitae, mapping competencies to live occupational ontologies, and measuring candidate interaction patterns during skill evaluations.

2. The Engineering Challenge

Converting unstructured human text into actionable, auditable skills intelligence presents three core software challenges:

  • Taxonomy Semantic Drift: Job titles and skill descriptions vary wildly across industries, demanding fuzzy matching and ontology mapping rather than naive keyword search.
  • Telemetry Recording: Evaluating how candidates interact with skill-matching assessments requires lightweight, low-latency telemetry logging that does not disrupt the user interface.
  • Institutional Governance & Privacy: Candidate data must be rigorously sanitized. No student records or proprietary research datasets can ever be exposed to unauthorized endpoints or third-party training pipelines.

3. My Role & Individual Contribution

As an AI & Software Systems Developer Intern within the engineering team, my core contributions encompass:

  • Backend API Integration: Developing RESTful endpoints using FastAPI and Next.js Route Handlers to receive CV documents, trigger parsing jobs, and return normalized competency structures.
  • Data Modeling: Designing relational schemas in PostgreSQL (via Supabase) to represent skills graphs, occupational hierarchies, and candidate session profiles.
  • Telemetry Instrumentation: Building database-backed logging structures to capture cognitive assessment milestones and user exploration journeys.
  • AI Integration Boundaries: Helping design prompts and schema validation contracts that enforce strict JSON output formatting from language model endpoints.

5. Key Technical Decisions

Component Choice Rationale
Frontend Next.js & TypeScript Provides type safety across complex occupational graph data structures, combined with fast server-side rendering for data visualization.
Microservices FastAPI (Python) High-throughput asynchronous request handling and natural ecosystem compatibility with data processing and NLP libraries.
Database Supabase (PostgreSQL) Combines powerful relational capabilities (constraints, foreign keys, JSONB columns) with managed Row-Level Security (RLS) policies.

6. Security, Privacy & Institutional Governance

Because this project operates within an academic research institution, privacy is engineered into the system architecture:

  • Zero External Data Leakage: Candidate resumes and personally identifiable information (PII) are scrubbed before any analytical inference occurs.
  • Protected Endpoints: Supabase Row-Level Security policies ensure that candidate session telemetry is accessible strictly by authorized researchers.
  • Clean Public Boundary: Public case study documentation strictly omits internal research datasets, private repository URLs, internal staging keys, and confidential institutional materials.

7. Current Status & Future Engineering

The system is currently undergoing active prototyping and internal evaluation within the Future of Learning laboratory. Current capabilities include CV skill parsing, occupational taxonomy navigation, and backend telemetry storage. Ongoing engineering focuses on refining graph visualization components and evaluating retrieval accuracy against benchmark occupational dictionaries.
